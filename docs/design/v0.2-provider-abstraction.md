## 1. Problem

The current LLM layer cannot support any other V0.2 feature.

| Problem | Location | Consequence |
|---|---|---|
| SDK client is built at import time with Gemini's base URL hardcoded | src/vinci/llm/client.py:13-16 | Adding a provider means editing the client |
| Model is a free-form string | src/vinci/llm/client.py:34 | No context-window or pricing knowledge |
| Provider quirk (Gemini `thought_signature`) lives in the generic client | src/vinci/llm/client.py:141-146 | Coupling; leaks into every provider |
| All failures collapse into `LLMAPIError` | src/vinci/core/exceptions.py:1 | Cannot distinguish retryable from fatal, so fallback is impossible |
| Response usage metadata is discarded | src/vinci/llm/client.py:119-160 | Token and cost tracking cannot be built |
| Agent depends on the concrete class | src/vinci/agents/base.py (self.llm.call) | Provider swap requires agent changes |

## 2. Goals

1. One provider protocol that agent code depends on.
2. At least three implementations: Gemini, OpenAI (direct), and Fake (tests).
3. Normalized request/response types carrying token usage.
4. Error taxonomy that lets callers decide retry vs fail vs fallback.
5. Zero behavior change: the 15 existing tests stay green after every phase.

## 3. Non-goals (deferred, each needs its own doc)

- Streaming (V0.2 layer 5)
- Fallback routing logic (layer 3)
- Cost computation (layer 2b)
- Typed message normalization for non-OpenAI wire formats (Anthropic/native)
- Prompt management, conversation management
- Multi-modal content

## 4. Key decisions

### D1 — Canonical wire format is OpenAI chat completions

Gemini is already consumed through its OpenAI-compatible endpoint. Both real
providers therefore share one message shape, so `messages: list[dict]` stays
canonical for now.

Rejected alternative: introduce a typed `Message` union immediately. It would be
an abstraction with only one wire format to justify it. Introduce it when the
first non-OpenAI provider (Anthropic) arrives.

Risk: message-level provider differences (role for tool results, system prompt
placement) stay provider-local until then.

### D2 — Providers take an `LLMRequest`; `LLMClient.call(messages, tools)` remains as facade

Providers receive one request object. Orchestration (model resolution, fallback,
usage aggregation) stays in `LLMClient`, which keeps the legacy signature the
agent and tests already use.

Rationale: fallback and context trimming later need to clone and mutate a request
in one place. Keeping the facade avoids touching `Agent` and all test fakes in
this phase.

### D3 — Providers are thin, policy-free transport adapters

A provider knows exactly one API family and does three things:

1. translate `LLMRequest` into SDK calls
2. map SDK exceptions into the error taxonomy
3. return `LLMResponse` including `Usage`

Providers never select models, retry, fall back, or compute cost. That is
`LLMClient`'s job. This keeps providers independently testable and prevents
policy from smearing across implementations.

### D4 — Second real provider is OpenAI direct; test provider is `FakeProvider`

The `openai` SDK is already a dependency: no new dependency, no new API concept,
and it proves config-level switching rather than message translation.

`GeminiProvider` subclasses `OpenAICompatibleProvider` and overrides only the
`thought_signature` extraction.

Anthropic is deferred because it would force D1 early.

### D5 — Error taxonomy with retryability

Mapped once, at the provider boundary. Callers (and later the fallback router)
branch on type, not on SDK internals.

### D6 — `usage` is optional on responses

`LLMResponse.usage: Usage | None`. Test fakes that predate this design remain
constructible without changes.

## 5. Interfaces

```python
# src/vinci/llm/types.py
@dataclass(frozen=True)
class ToolCall:
    id: str
    name: str
    arguments: dict
    thought_signature: str | None = None

@dataclass(frozen=True)
class Usage:
    prompt_tokens: int
    completion_tokens: int
    total_tokens: int

@dataclass(frozen=True)
class LLMRequest:
    model: str
    messages: list[dict]
    tools: list[dict] | None = None
    temperature: float | None = None
    max_tokens: int | None = None
    response_format: dict | None = None   # reserved for structured outputs

@dataclass(frozen=True)
class LLMResponse:
    content: str | None
    tool_calls: list[ToolCall]
    usage: Usage | None = None
    finish_reason: str | None = None
    raw_model: str | None = None          # model actually served
```

```python
# src/vinci/llm/protocol.py
class LLMProvider(Protocol):
    name: str
    async def complete(self, request: LLMRequest) -> LLMResponse: ...
    # stream() is added by the streaming design, not here.
```

```python
# src/vinci/llm/errors.py
class LLMError(Exception): ...

class ProviderError(LLMError):
    provider: str
    retryable: bool

class ProviderUnavailable(ProviderError):   retryable = True   # 5xx, timeout, connection
class RateLimited(ProviderError):           retryable = True   # 429
class AuthFailed(ProviderError):            retryable = False  # 401, 403
class RequestRejected(LLMError):            retryable = False  # 400
class ContextWindowExceeded(LLMError):      retryable = False  # retry on larger model only
class InvalidResponse(LLMError):            retryable = True   # bad JSON, bad tool args, schema mismatch
class AllProvidersFailed(LLMError): ...                        # added with fallback
```

`LLMAPIError` is kept as a deprecated alias base during migration so existing
imports keep working.

```python
# src/vinci/llm/catalog.py
@dataclass(frozen=True)
class ModelInfo:
    key: str                 # e.g. "gemini-3.8-flash"
    provider: str            # "gemini" | "openai" | "fake"
    model_id: str            # wire model name
    context_window: int
    max_output_tokens: int
    input_price_per_1m: float | None
    output_price_per_1m: float | None
    capabilities: frozenset[str]   # {"tools", "streaming", "structured"}
```

`LLMClient` resolves a `model` key through the catalog, picks the provider, and
calls `complete()`. Phase C only.

## 6. File layout

```
src/vinci/llm/
  types.py                  # new: ToolCall, Usage, LLMRequest, LLMResponse
  errors.py                 # new: taxonomy
  protocol.py               # new: LLMProvider
  catalog.py                # new (Phase C): ModelInfo registry
  client.py                 # rewritten as facade; re-exports legacy names
  providers/
    __init__.py
    openai_compatible.py    # shared transport
    gemini.py               # subclass: thought_signature only
    fake.py                 # scripted responses/errors for tests
```

Backward compatibility: `client.py` continues to export `CallResponse`,
`ToolCallRequest`, and `LLMClient`. Legacy `CallResponse` and `ToolCallRequest`
are thin aliases for `LLMResponse` and `ToolCall`, so no test imports change.

## 7. Phased migration (each phase ends with the 15 tests green)

Phase A — types, errors, protocol, `FakeProvider`, `OpenAICompatibleProvider`,
`GeminiProvider`; `LLMClient` becomes a delegating facade.
Phase B — plumb `usage` through `CallResponse`/`LLMResponse`; expose per-run
aggregate on `AgentResult`.
Phase C — model catalog and config-driven model selection.

Stop after C. Fallback, cost, and streaming are separate designs.

## 8. Configuration

```
GEMINI_API_KEY=...
OPENAI_API_KEY=...
LLM_PRIMARY_PROVIDER=gemini        # Phase C
LLM_DEFAULT_MODEL=gemini-3.8-flash # Phase C
```

`Settings` gains `openai_api_key`, `llm_primary_provider`, `llm_default_model`.
No secrets in code; `.env` stays gitignored.

## 9. Testing strategy

- One contract test module run against every provider:
  - final answer, tool call parsing, invalid tool arguments
  - usage present when the provider supplies it
  - error mapping (mock SDK exceptions, no network)
- `FakeProvider` always runs.
- Gemini/OpenAI contract tests are skipped unless the corresponding key exists.
- No network calls in the default suite. This rules out tests like
  tests/test_rag_retriever.py as written.

## 10. Acceptance criteria (mapped to roadmap.txt V0.2)

- [ ] Switching provider is a config change; `Agent` is untouched.
- [ ] All 15 existing tests pass after every phase.
- [ ] Contract tests pass for Fake; pass for Gemini/OpenAI when keys present.
- [ ] Token usage is visible on the response (Phase B) and aggregated per run.
- [ ] Provider failures map to typed, retryability-aware errors.

## 11. Risks

- Gemini's OpenAI-compatible endpoint can change or omit usage fields. Treat
  `usage` as optional everywhere.
- `ALL_PROVIDERS` config validation can drift from the catalog; one source of
  truth (catalog) validates at startup.
- README/roadmap conflict will confuse future sessions; fix README after V0.2.
